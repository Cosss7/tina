# 引擎适配契约

> 实现或修改 tinad 的引擎适配、会话管理、取消与恢复时读取本文。
> 系统边界见 [架构入口](architecture.md)，线格式见 [执行协议](execution-protocol.md)，具体引擎行为见 [tinad](tinad.md#引擎接入)。

## 1. 边界与默认形态

控制面维护项目业务和 Run 状态；tinad 管理执行资源与回传记录；适配器翻译引擎协议和执行证据。

**适配器默认作为 tinad 内部模块，通过引擎已有的进程协议、网络接口或 SDK 驱动引擎。** 引擎本身仍运行在独立进程或外部服务中。需要独立运行时、插件宿主或额外隔离时，允许外置适配器，但不要求所有引擎都增加一层适配进程。

控制面与 tinad 的执行协议负责跨机器通信；tinad 内部适配接口负责调用与事件语义。两者独立设计，内部函数调用不必经过自定义 TCP 协议。外置适配器需要实现相同语义，再选择对应传输。

### 实现语言

| 组件 | 选择 |
|---|---|
| 控制面 | Go，维护业务规则、权威数据与执行协议 |
| tinad | Go，标准库优先，管理会话、连接、进程和本机执行资源 |
| 普通引擎适配器 | Go，默认作为 tinad 内部模块，直接使用引擎已有协议 |
| dsh 进程内插件 | 需要访问 dsh 内部能力时使用 TypeScript，运行在 dsh 的扩展环境中 |
| 必须复用其他语言 SDK 的特殊接入 | 先评估 SDK 收益，再按需增加薄的外置适配器，不作为每种引擎的默认要求 |

操作语义与线协议保持语言无关，tinad 侧通过 Go 接口调用。dsh 适配模块直接驱动原生 stdio 协议，访问引擎内部能力时可使用对应插件。语言选择与取舍见 [产品愿景](vision.md#31-选型总表)。

适配器所属的模块关系与进程边界见 [tinad 内部结构](tinad.md#内部结构)。适配实现复用原生运行环境，能力声明由实际协议和配置决定。

## 2. 注册与复用

适配代码按引擎接口或协议族复用。新增 Router、Worker 或模型配置通常只增加 Agent 配置，不增加适配实现。

| 对象 | 职责 |
|---|---|
| 引擎定义 | 标识、启动方式、默认能力与配置规则；兼容同协议的引擎可共享实现 |
| 适配工厂／客户端 | 探测可用性，创建或恢复会话，解释引擎差异 |
| 会话实例 | 保存一个原生会话的运行状态，发送输入、收事件、处理交互与中断 |
| 通用进程监管 | 启动、退出观察、超时及进程树清理；适配器补充引擎特有的停止协议 |

复用的是代码和工厂，不是多个会话共用一份可变状态。会话实例之间必须隔离原生句柄、当前活动、事件订阅和待答复请求。

同协议接入优先采用启动配置与薄的差异处理，避免复制整套会话和进程生命周期。

## 3. 身份与持久句柄

| 标识 | 含义与规则 |
|---|---|
| Agent ID | 控制面中的项目成员身份，独立于引擎品牌和进程 |
| Run ID | 一次业务尝试，允许关联已有会话；重试产生新的 Run |
| 命令 ID | 一次派发或输入操作的幂等标识；补传与重试投递保留该标识 |
| 会话 ID | Tina 对引擎交互上下文的逻辑标识，不使用进程 PID 代替 |
| 原生持久句柄 | 引擎返回的会话 ID、thread ID、恢复 token 或会话文件定位，按引擎解释 |
| 活动标识 | 当前输入或回合的标识，用于关联回执、事件、终态和取消；需要时同时保存原生 turn ID |
| 执行实例标识 | 区分同一会话的不同进程实例，防止重启前的迟到事件影响新执行 |

持久句柄至少关联引擎类型、Tina 会话 ID、原生句柄和恢复所需的非敏感元数据。控制面维护与 Run、Agent、tinad 的业务关联；tinad 管理本机句柄的使用及尚未回传的执行事实。凭据通过受控引用提供，不放入普通日志或注册广播。

会话历史、运行进程和业务尝试具有不同生命周期。Run 结束不必删除会话；释放引擎进程不等于删除持久历史。更换执行机器后是否能使用原生句柄，需要适配器核实，不能只复制一个 ID 就宣称恢复成功。

## 4. 最小操作与可选能力

操作名用于描述语义；Go 接口位于 `services/tinad/internal/engine`，线格式与状态规则见 [执行协议 v1](execution-protocol.md)。

| 操作 | 约定 |
|---|---|
| 探测与描述能力 | 返回引擎可用性、版本或诊断，以及本次配置实际支持的能力 |
| 创建会话 | 建立上下文，返回会话实例与原生身份；进程启动失败和协议未就绪要分别报告 |
| 恢复会话 | 使用原生持久句柄继续交互；不支持或恢复被拒绝时明确返回，不能悄悄创建新会话 |
| 提交输入 | 关联命令、Run、会话和活动，返回投递结果；最终执行结果由事件或终态结果另行报告 |
| 订阅执行事件 | 输出统一的消息、工具、用量、交互请求和终态事件，并关联会话、活动和执行实例 |
| 中断当前活动 | 指定需要停止的活动，返回是否请求成功及后续停止证据；不能取消已经被新活动替代的旧回合 |
| 释放运行时 | 释放进程、连接与订阅，报告清理结果；保留可持久恢复的历史，除非另有明确删除操作 |
| 回答引擎交互请求 | 可选；按请求 ID 回应工具授权或提问，与项目计划审批分别建模 |

恢复、运行中补充输入、审批交互等按能力声明开放。没有实现的可选操作返回明确的不支持结果，不用空成功响应占位。

引擎定义和注册表检查声明能力与实现入口是否一致；会话可按引擎版本、配置和运行状态缩小能力。实际行为仍需契约测试验证，存在同名方法不等于已经满足能力语义。

### Go 接口与调用生命周期

| 接口 | 操作 |
|---|---|
| `Driver` | `Definition`、`Probe`、`Create`；按引擎或协议族复用 |
| `Resumer`（可选） | `Resume`；检查真实句柄及可用能力 |
| `Session` | `Info`、`Submit`、`Updates`、`Close`；每个实例维护隔离状态 |
| `Interrupter`（可选） | `Interrupt(ctx, activityID)`；调用者先选择准确实例 |
| `Responder`（可选） | `Respond(ctx, requestID, answer)`；调用者先校验实例、活动和待答请求 |

Capabilities 包含 resume、interrupt（none/turn/process）和 respond。静态声明、Probe 与会话能力逐层收窄；注册表拒绝缺少恢复入口的驱动，创建时拒绝缺少中断或交互入口的会话，并尝试释放无效运行时。

Submit 的 context 约束本次调用等待，活动生命周期由显式中断和终态管理。Close 释放运行时，保留原生历史；恢复后的新实例不能沿用旧实例的调用或事件。

## 5. 投递与执行结果

适配器将原生接受证据、活动开始、执行终态和停止证据分别映射到 [执行协议的状态](execution-protocol.md#4-接受终态与取消)。回执丢失时保留待确认或 unknown，按 [重复与对账规则](execution-protocol.md#5-重复断连与恢复规则) 处理，不能重新提交可能已经执行的输入。

统一事件不能仅有文本：要能识别输入、活动开始、交互请求、工具调用与结果、用量、活动终态和运行时退出。终态保留引擎提供的原因与证据，不能把无法识别的结束原因默认为成功。

控制面接收并去重执行事实，按业务规则维护 Run 和卡片状态；适配器不创建任务、批准计划、终审或直接写项目状态。终态后的资源清理结果单独记录，不把一次已经完成的执行改写成另一种业务结果。

## 6. 取消与资源释放

**中断活动、释放运行时、清理相关工具进程分别报告。** 一个 `interrupt=true` 或成功发送停止信号，不能替代停止证明。

停止结果需要表达：

- 取消目标及请求是否被接受、拒绝或无法确认。
- 当前活动是否已经结束；会话能否继续使用。
- 本次操作是否升级为关闭引擎进程。
- 受 tinad 管理的父进程及相关工具工作负载是否已退出，或仍无法证实。
- 终态或清理错误、仍需对账的原因。

优先使用引擎原生取消能力；超时后的进程级终止是显式降级，须记录它对会话续跑的影响。进程树监管由 tinad 的公共设施提供，适配器负责原生取消与引擎特有资源释放。远程服务等不由 tinad 持有的进程，要按实际可观察范围报告，不能伪造本机退出证明。

收到取消请求后先保持请求状态。只有确认对应活动停止或已经取得其他有效终态，控制面才结算该 Run；工具仍在运行或退出不可证实时，保留清理／对账信息。无法确认时不合成“已取消”来开启新的执行。

## 7. 一致性约束

| 场景 | 约束 |
|---|---|
| 同一适配实现创建多个 Agent 会话 | 配置可复用，消息、句柄、活动和取消目标不串线 |
| 发布某项能力 | 注册表能拒绝缺少入口的声明，契约测试证明实际行为；不支持时明确拒绝 |
| 释放后恢复 | 用原生句柄恢复并继续交互；历史缺失或不可恢复时明确报告，未伪装为续接成功 |
| 投递后丢失回执 | 返回待确认或结果未知并对账，不产生第二次执行 |
| 取消与完成竞争 | 仅结束目标活动，终态不被迟到消息覆盖；运行时与工具清理有独立结果 |
| SDK、原生协议和外置实现 | 遵守同一操作语义，控制面不依赖具体调用方式 |
