# 文档规则

Tina 的文档分两层：**决策记在 notes 里，投影放在 docs 里。**

## 分工

| 位置 | 放什么 | 规则 |
|---|---|---|
| `.agents/notes/` | 决策记录：定过什么、推翻过什么、为什么 | 只追加。不改历史结论，推翻就写新的 |
| `docs/` | 当前共识的投影：现在是什么样 | 只写结论，不写争论过程 |
| `docs/archived/` | 过时的投影 | 保留可查，不再维护 |

**两边冲突时，以决策记录为准。** `docs/` 可能滞后，发现不一致先去查 notes。

## 当前文档

| 文件 | 回答什么 | 什么时候更新 |
|---|---|---|
| `vision.md` | 产品最终形态：故事、架构、技术选型 | 决策改变了产品方向或架构时 |
| `h0.md` | 当前里程碑做什么、怎么算完成 | 里程碑范围变化时 |
| `versioning.md` | 版本号、tag、发布流程 | 发布规则变化时 |

## 什么时候写哪边

1. 讨论出一个结论 → 记进 `.agents/notes/` 的决策记录。
2. 这个结论改变了"现在是什么样" → 同时改 `docs/` 里对应的投影。
3. 只是过程、备选方案、被推翻的想法 → 只进 notes，不进 docs。

## 过时怎么处理

- **整份过时**（被新文档取代）：移到 `docs/archived/`，在下面的登记表加一行。
- **局部过时**：直接改。git 里有历史，正文里不需要留痕。

## 归档登记

|---|---|---|
| （暂无） | | |

## 命名

- `docs/` 扁平，不加数字前缀。文档超过五份再按目录重组。
- 归档文件带日期前缀 `YYYY-MM-DD-`，方便排序。

## 不做什么

- **不建 `docs/adr/`**：决策记录就是 ADR，再建一套会分叉，让人不知道该信哪个。
- 不在 `docs/` 里写"考虑过 A 和 B，最后选 B"——那是 notes 的内容。
- 不改写决策记录里的历史结论，只做补链接、补日期这类修补。
